A metade que protege — do lado do servidor

O botão Comprar nunca fala com a Stripe directamente. Chama uma função de servidor, que é a única que tem a chave secreta. O site só conhece a chave publicável (pk_…), que é pública por desenho.

// 1. o site pede a sessão de pagamento (não sabe preços nem chaves)
const r = await fetch('/api/comprar-foto', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ fotoId: 'foto-101' })
});
const { url } = await r.json();
window.location.href = url;          // vai para o pagamento

// 2. no SERVIDOR (Edge Function): o preço vem da base, nunca do browser
//    o webhook do fornecedor é que marca a compra como paga
//    — nunca uma variável do JavaScript, nunca o "voltou da página de sucesso"

// 3. só depois, para descarregar:
//    a função confirma na base que aquela compra está PAGA,
//    e só então emite um link assinado ao balde PRIVADO, válido 5 minutos.
const { data } = await supabase.storage
  .from('fotos-originais')            // balde PRIVADO, sem URL público
  .createSignedUrl(caminho, 300);     // 5 minutos e morre

As três regras que não se quebram

Uma. O ficheiro em alta resolução nunca tem endereço público. Se tiver, todo o resto é teatro.

Duas. Quem decide que a compra está paga é o webhook do fornecedor, no servidor. O regresso da pessoa à página de sucesso não prova pagamento nenhum — ela pode escrever esse endereço à mão.

Três. A chave secreta vive só na função de servidor. O HTML é público: qualquer visitante lê o código-fonte da página.
